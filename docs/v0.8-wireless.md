# V0.8 无线环境观测与调查

在已注册手机上连接设备，打开「无线 → 无线网络」。默认按 SSID 显示，可切换到「接入点」或「信道」。点网络名查看不同 BSSID，再点 BSSID 查看信号、信道、安全配置和网络活动。隐藏网络按 BSSID 分开显示。

## 用手机进行一次观测

1. 在「持续观测」点「开始观测」，选择时长并确认。默认间隔 30 秒、时长 10 分钟，时长上限 60 分钟。树莓派同时只运行一个任务。
2. 首次完成的观测建立基线。之后首次出现的 BSSID 计入「新增」，相同 BSSID 再次出现只更新历史。切换手机页面或暂时断开热点后，树莓派继续计时；重新连接可查看进度。
3. 点「停止观测」并确认，或者等待到期。摘要给出实际完成的观测次数、接入点数量、新增数量、信道及安全配置变更。单个信号读数的变化只计入观测历史。
4. 从无线首页或 AP 详情点 AI 分析按钮，检查预填的问题，再点发送。针对某个 AP 的提问会带上 BSSID。报告区分已确认事实、可疑现象、支持证据、不确定信息和下一步建议。「技术详情」可以核对原始记录和关联事件。

**采样方式由设备决定。** 已有运行中的 Kismet Wi-Fi 监听源时，会话定时读取该来源；使用 Managed Scan 时，扫描助手检查扫描接口和管理热点的物理无线电。只有内置无线电且它正在提供热点时，持续普通扫描显示「条件不足」。保留的单次手动扫描有独立的操作确认。

**报告保留范围。** MCP 进程保留当前或最近一次会话，开始新会话会替换上一份报告，重启 MCP 会清空会话。V0.7.4 的普通扫描日志仍按本次开机保存。时间线以设备记录时间为准；截断的样本、缺失的来源和采样间隙都会限制结论。

## 设备数据如何到达手机和 Agent

| 层次 | 提供的数据 |
| --- | --- |
| 观测 | 继续使用现有 SSID/BSSID 聚合、Managed Scan 结果和限定来源的 Kismet 视图；各采样带有观测时间和来源。 |
| 调查 | 对指定 BSSID 关联设备记录、信号历史、会话变化和 Kismet 事件。对照历史可辨认已记录的信道或安全配置变化。 |
| 展示 | 手机显示数量、状态、时间线和活动摘要；用户主动展开后查看技术记录。Agent 通过只读工具取得完整的有界证据。 |

| MCP 工具 | 参数和用途 |
| --- | --- |
| `start_wireless_monitoring` | 已注册操作者明确传入 `confirm=true`。可选 `interval_seconds`（30–3600）和 `duration_seconds`（1–3600）。 |
| `get_wireless_monitoring_status` | 返回会话状态、来源、实际完成次数、运行时间及总结。 |
| `stop_wireless_monitoring` | 已注册操作者明确传入 `confirm=true`，请求树莓派停止。 |
| `get_wireless_events` / `get_signal_history` | 查看已记录的无线变化、来源和时间序列。 |
| `get_wireless_investigation` | 提供 `ap_id`（优先 BSSID）取得第一页；用相同的 `ap_id`、返回的 `snapshot_id` 和 `next_offset` 继续，直至 `next_offset` 为空。证据快照保留至多五分钟，过期需重新查询。 |

AI 只获得已启用的只读工具。开始和停止操作由手机按钮明确确认。发送给云端模型的调查上下文保留证据来源、时间及限制。

## 从 V0.7.4 更新

在树莓派上准备好本版源码，到仓库根目录执行。MCP 的实际工作目录由 systemd 读取。两个助手沿用既有的受限服务，下一次调用时加载新文件。

```bash
(
    set -eu
    src=$(realpath raspberry/mcp_server)
    work=$(systemctl show -p WorkingDirectory --value piagent-mcp.service)
    test -n "$work"
    test -d "$work/raspberry/mcp_server"
    dst=$(realpath "$work/raspberry/mcp_server")
    worker=$(systemctl show -p User --value piagent-mcp.service)
    test -n "$worker"
    if [ "$dst" != "$src" ]; then
        for module in capabilities managed_scan monitoring_session phone_captures phone_radio server wireless_intelligence wireless_service; do
            sudo install -o "$worker" -m 0600 "$src/$module.py" "$dst/"
        done
    fi
    sudo install -m 0644 "$src/managed_scan.py" /usr/lib/piagent-managed-scan/raspberry/mcp_server/
    sudo install -m 0644 "$src/phone_radio.py" /usr/local/lib/piagent-sources/raspberry/mcp_server/
    sudo systemctl restart piagent-mcp.service
)
```

## 实机验收

按需在有线 SSH 里运行以下只读命令。完成手机端的开始、停止和查询操作即可覆盖一轮验收，每项等待最多三分钟。设备上的真实行为由设备所有者记录。

```bash
iw dev
systemctl is-active piagent-mcp.service piagent-hotspot.service piagent-ble-time-sync.service
systemctl show piagent-managed-scan@monitoring.service -p ActiveState -p Result -p ExecMainStartTimestamp
journalctl -u piagent-mcp -u piagent-managed-scan@monitoring.service --since '3 minutes ago' -n 30 --no-pager
```

| 项目 | 操作与判据 |
| --- | --- |
| T1–T4 | 查看同一网络的多次采样。相同 BSSID 显示一次，同名不同 BSSID 分组，隐藏 BSSID 各自独立。具备两种观测来源时，在技术详情核对来源。 |
| T5–T6 | 在具备合适来源的设备上开始观测，保持手机连接管理热点并刷新设备能力。看到至少一次完整采样后停止；最终状态为已停止，之后次数不再增长。 |
| T7–T8 | 点开 BSSID 查看带时间、来源和 dBm 的记录。对照会话结束摘要检查基线和新增 BSSID。没有新增设备时，新增数为零也有效。 |
| T9–T10 | AP 默认页查看活动摘要，进入「技术详情」再看记录和证据。点击 AI 分析并发送，核对回复中的观测范围、来源和不确定信息。使用真实 DeepSeek 的这一步需要手机可访问云端。 |
| T11 | 使用与管理热点共用无线电且没有活动监听源的配置。页面应说明持续普通扫描受限；观察扫描单元启动时间未增加，手机仍可刷新设备能力。没有独立扫描硬件时记录这一结果，将成功采样的实机条目标为待验。 |
| T12 | 手机连接原热点，用已有身份连接设备，进入蓝牙校时并实际完成一次。 |
