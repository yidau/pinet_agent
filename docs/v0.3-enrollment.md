# PiAgent V0.3 永久二维码注册

永久二维码是所有者的注册凭据。二维码权限只用于登记手机公钥，二维码本身应保存在所有者可控的位置。注册后的手机有独立的 BLE 身份、MCP Bearer 令牌和 WPA2 凭据。手机私钥由 Android Keystore 或 iOS Keychain 持有。Android 11 起通过系统弹窗保存热点，iOS 通过系统热点配置请求。 [Android Wi-Fi 配置](https://developer.android.com/develop/connectivity/wifi/wifi-save-network-passpoint-config) · [iOS 热点配置](https://developer.apple.com/documentation/networkextension/nehotspotconfigurationmanager)

## 安装和首次注册

从全新 Ubuntu 树莓派开始，请按 [README 安装指南](../README.md#1-准备一台新的-ubuntu-树莓派) 配置热点、HTTPS、蓝牙服务并生成永久二维码。安装后，用 App 的「手机注册」扫码。已注册的手机再次连接时仍使用原手机密钥和独立凭据。

## GATT 与认证协议

服务 UUID 为 `7ab410a0-fd6a-49f1-91bb-40e71e672100`。特征使用同一前缀，末尾 `01` 为设备信息、`02` 为挑战、`03` 为写请求、`04` 为读取结果。设备信息和挑战采用 JSON，长读取使用 ATT offset。请求和结果分片长度最多 20 字节，以支持默认 MTU。

- 永久二维码 JSON 包含 `version`、`device_id`、`enrollment_secret`、`public_key_fingerprint`、`ble_service`。二进制字段使用无填充 base64url。指纹为 `sha256:` 加树莓派 P-256 非压缩公钥的 SHA-256 小写十六进制。
- `DeviceInfo` 给出版本、Pi 标识、公钥和指纹。客户端以二维码中的指纹核对公钥。树莓派用该公钥对应的私钥签名 `piagent/enrollment/challenge/v1`、设备 ID、32 字节随机 nonce 和临时 ECDH 公钥。待签字段用换行连接，末尾无换行。
- 手机发送 `[1]` 开始，多个 `[2]+数据` 写入 JSON，`[3]` 提交。请求包含 `mode`、`nonce`、`device_name`、`public_key`、`ephemeral`、`proof`、`signature`。签名数据依次为 `piagent/enrollment/request/v1`、Pi ID、nonce、Pi 临时公钥、模式、手机长期公钥、手机临时公钥和 base64url 手机名称，各字段以换行分隔。`register` 要求 HMAC-SHA256 证明，HMAC 密钥由二维码秘密以 `piagent/enrollment/key/v1` 派生。`resume` 复用手机签名，证明字段为空。
- `Result` 每页为状态、两字节大端总长和最多 17 字节数据。状态 `0` 暂无结果，`1` 已就绪，`2` 拒绝，`3` 正在处理。以 `[4,偏移高字节,偏移低字节]` 选择后续页。凭据为 AES-256-GCM 密文，由双方 P-256 ECDH 结果经 HKDF-SHA256 派生，盐为 nonce，info 为 `piagent/enrollment/response/v1`。认证附加数据是手机签名的原文，响应由 12 字节 IV、密文和 16 字节标签组成。
- 挑战每次提交后消耗，按 BlueZ 连接对象隔离，断线后失效。错误尝试限速。V0.3 校时先用相同手机密钥认证，保留原校时特征和帧长。写请求原 nonce 位置携带 `HMAC-SHA256(ble_key, "piagent/time-sync/request/v3" + 原请求帧)` 的前八字节，读取仍返回本轮随机 nonce。树莓派使用本轮 nonce 重算鉴别码，拒绝旧帧。旧部署仍可按原有可信蓝牙配对方式校时。

## 本地管理

```sh
cd /opt/piagent-time-sync
sudo -u piagent-ble .venv/bin/python -m raspberry.enrollment.admin list
sudo -u piagent-ble .venv/bin/python -m raspberry.enrollment.admin revoke DEVICE_ID
sudo -u piagent-ble .venv/bin/python -m raspberry.enrollment.admin registration off
```

登记表记录名称、设备 ID、注册时间、授权状态和最近的 BLE 身份验证时间。审计表记录注册、撤销请求和撤销完成。撤销先停止该身份的应用层和校时授权，再删除对应的热点凭据并等待 hostapd 确认。若热点更新失败，状态为 `revoking`，可再次执行该设备的撤销动作。暂停新注册时，原有设备仍可认证和使用。
