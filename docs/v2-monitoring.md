# PocketNet V2 仪表盘与常态监控

V2 以 `main@5375332` 为审查基线，直接继承 PR #2 的 `ceeef6b`。手机使用同版 Android `1.2.0+15`。旧 APK 可以订阅原格式快照。V2 手机连接旧树莓派时保留基础快照，界面提示升级设备端。

## 仪表盘和无线列表

仪表盘显示最近收到的快照。超过 7 秒没有新快照时标记过期，12 秒时触发重新连接。有线 SSH、手机注册、热点和 BLE 校时沿用设备现有身份。仪表盘随屏幕高度布局，无线观测增加连续观测时间、当前信道和丢弃包，系统资源增加 CPU 频率、内存使用率和 I/O 压力。CPU 和内存的颜色使用树莓派报告的资源压力，仪表盘温度达到 65 °C 标黄、达到 75 °C 标红。

连续观测时长以实际确认的监听源为准，从 USB 和 Kismet 均就绪时开始。USB 拔插、监听中断或数据源重建会重置该时长。切换采集档位会短暂中断观察，实际档位以 Kismet definition 回读为准。

| 档位 | Kismet 输入 |
|---|---|
| 轻量 | 管理帧和 EAPOL，默认档 |
| 均衡 | 普通数据帧只保留头部 |
| 扩展 | 接收更多数据帧输入，仍遵守空口覆盖限制 |

三档均保留既有信道轮巡和关闭 PCAP 的默认设置。一级资源压力给出提示，二级限制列表详情并尝试回退到轻量。解除压力后由用户重新选择档位。

从构建 19 起，打开 App 建立监控连接或点「重新连接」会在设备就绪后默认请求扩展。手动切档与设备端的压力回退优先，切档引起的遥测重连不重复请求默认档位。

无线列表显示最近五分钟内可归属到指定监听源的观测。服务端最多保留 128 个 AP 和 256 个客户端，每次返回最多 32 条，手机自动读完同一观测快照。仪表盘将组件状态用颜色和图标显示，点击查看原因和详情。当前告警轮询正常时，「告警接入」为绿色，轮询限制显示在详情内。常态监控将设置折叠，首屏只展示最近 30 秒有观测流量的 BSSID，按 SSID 分组。「查看所有」打开同页可滚动、可搜索的面板，并显示全量 AP（含零流量和暂无流量样本），点击 BSSID 查看详情。页面可见时每约 12 秒自动更新已读取的观测。客户端关联要求 Kismet 的关联映射和客户端最近的 BSSID 一致。临时关注在手机内存中维护，树莓派整机重启后清空；仅遥测进程重启时保留关注。SSID 关注对已观测映射到该 SSID 的 BSSID 事件排序同样生效。

### 30 秒观测流量

在「常态监控」打开「监控设置」，选择均衡或扩展档，等待出现第一个完整的 30 秒采样窗口。每个 SSID 行显示设备端汇总，展开后查看各 BSSID。隐藏 SSID 的流量按 BSSID 单列。轻量档过滤普通数据帧，此时可以用「查看所有」浏览 AP。流量字段由 Android `1.2.0+17` 起显示，单屏概览及「查看所有」由 `1.2.0+18` 起提供。

C++ 遥测每约 5 秒读取 Kismet 的 `dot11.device.datasize`，按单调时间计算 BSSID 计数差，再将同一窗口的 BSSID 汇总到各 SSID。采样点未对齐 30 秒边界时，按该区间内的字节增量插值，手机以「约」标示。计数回退、Kismet 重启、采集档位切换或样本断档都会清除对应的统计基线。只有有效样本才显示零，汇总缺失部分 BSSID 时标为部分观测。计数窗口保存在 RAM 中，继续使用有界分页和原有无线来源验证。

流量只覆盖监听网卡实际捕获到的数据，不含跳频期间漏掉的帧。实机验收可在自有 AP 上运行一次可控的数据传输，观察对应 BSSID 和 SSID 的计数增加，停止传输后观察数值随窗口滑出而回落。切回轻量档核对未采集提示。

## 高危确认和通知

原生 Kismet 告警使用独立的有界 REST 轮询。仪表盘会报告 `polling_best_effort`，中断期间可能漏报。规则版本 1 只提高具备 BSSID、时间、描述与高严重度的原生管理帧告警，包括 `DEAUTHFLOOD`、`BCASTDISCON`、`DOT11CSAFLOOD`、`DOT11CSASPOOF`。发现描述表示观测到疑似行为。单条原生 Kismet 告警即使达到高危阈值也仍标记 LIMITED（单源证据），不标记 CORROBORATED。高危事件只有收到 SQLite 成功提交的异步回执后才进入去重集合；提交失败会在有界 RAM 中保留候选并重试，最长 180 秒后丢弃并累计交付缺口。

设备端高危队列逻辑上限 32 MiB，SQLite 主库上限约 36 MiB，另外需要回滚日志空间。180 秒按 Linux 启动时钟计量。满额优先保留更高风险，同级保留较新记录。整机重启会丢弃上一轮未确认副本。普通快照和事件继续使用有界 RAM 缓冲。

手机 SQLite v2 保留旧历史和游标，高危档案单独长期保存。手机提交数据库事务后确认同一 durable ID，按 ID 去重。Android 用户可在常态监控开启持续接收，前台服务保持所用 Flutter 引擎及同一订阅。离开设备热点、关闭通知或系统停止进程会限制接收。

## 升级和回滚

使用 V2 更新包内的 `install.sh` 和同目录 SHA-256 通过有线 SSH 安装。安装器增加本机恢复 socket 和唯一高危 StateDirectory，保留注册库、CA、热点密钥和 USB 绑定。组件恢复只接受预定义动作。若需回滚，用 V2 安装器安装此前版本的 ARM64 更新包及对应 SHA-256。旧版不读取 V2 高危队列，V2 再次启动时按开机代际和原期限处理。

## 实机验收

1. 在手机安装同版 APK，确认已有注册和 BLE 校时可用。仪表盘显示真实数据，关掉连接后可以重新连接。
2. 拔下外接网卡，验证管理热点依然可用且计时停止。插回原 USB 口后，确认监听恢复并开始新的一段计时。
3. 选择轻量、均衡、扩展，核对回读档位、采样覆盖和客户端列表。验证关注规则在短暂断连后保留，在设备整机重启后清空。
4. 在受控测试中用模拟高危告警检查档案、重复投递、确认和过期。以 Android 通知权限开启、锁屏和 Wi-Fi 变化为条件分别确认持续接收。
5. 检查有线 SSH、服务启动及回滚。功耗、掉线恢复、后台运行、SD 写入和 2 GB 设备资源目标以实机记录为准。
