# PocketNet V2 仪表盘与常态监控

V2 以 `main@5375332` 为审查基线，直接继承 PR #2 的 `ceeef6b`。手机使用同版 Android `1.2.0+15`。旧 APK 可以订阅原格式快照。V2 手机连接旧树莓派时保留基础快照，界面提示升级设备端。

## 仪表盘和无线列表

雷达按实际收到的新快照启动一轮。超过 7 秒没有新快照时标记过期，12 秒时触发重新连接。有线 SSH、手机注册、热点和 BLE 校时沿用设备现有身份。

连续观测时长以实际确认的监听源为准，从 USB 和 Kismet 均就绪时开始。USB 拔插、监听中断或数据源重建会重置该时长。切换采集档位会短暂中断观察，实际档位以 Kismet definition 回读为准。

| 档位 | Kismet 输入 |
|---|---|
| 轻量 | 管理帧和 EAPOL，默认档 |
| 均衡 | 普通数据帧只保留头部 |
| 扩展 | 接收更多数据帧输入，仍遵守空口覆盖限制 |

三档均保留既有信道轮巡和关闭 PCAP 的默认设置。一级资源压力给出提示，二级限制列表详情并尝试回退到轻量。解除压力后由用户重新选择档位。

无线列表显示最近五分钟内可归属到指定监听源的观测。服务端最多保留 128 个 AP 和 256 个客户端，每页最多 32 条。客户端关联要求 Kismet 的关联映射和客户端最近的 BSSID 一致。临时关注在手机内存中维护，树莓派整机重启后清空。

## 高危确认和通知

原生 Kismet 告警使用独立的有界 REST 轮询。仪表盘会报告 `polling_best_effort`，中断期间可能漏报。规则版本 1 只提高具备 BSSID、时间、描述与高严重度的原生管理帧告警，包括 `DEAUTHFLOOD`、`BCASTDISCON`、`DOT11CSAFLOOD`、`DOT11CSASPOOF`。发现描述表示观测到疑似行为。

设备端高危队列逻辑上限 32 MiB，SQLite 主库上限约 36 MiB，另外需要回滚日志空间。180 秒按 Linux 启动时钟计量。满额优先保留更高风险，同级保留较新记录。整机重启会丢弃上一轮未确认副本。普通快照和事件继续使用有界 RAM 缓冲。

手机 SQLite v2 保留旧历史和游标，高危档案单独长期保存。手机提交数据库事务后确认同一 durable ID，按 ID 去重。Android 用户可在常态监控开启持续接收，前台服务保持所用 Flutter 引擎及同一订阅。离开设备热点、关闭通知或系统停止进程会限制接收。

## 升级和回滚

使用 V2 更新包内的 `install.sh` 和同目录 SHA-256 通过有线 SSH 安装。安装器增加本机恢复 socket 和唯一高危 StateDirectory，保留注册库、CA、热点密钥和 USB 绑定。组件恢复只接受预定义动作。若需回滚，用 V2 安装器安装此前版本的 ARM64 更新包及对应 SHA-256。旧版不读取 V2 高危队列，V2 再次启动时按开机代际和原期限处理。

## 实机验收

1. 在手机安装同版 APK，确认已有注册和 BLE 校时可用。仪表盘显示真实数据，关掉连接后可以重新连接。
2. 拔下外接网卡，验证管理热点依然可用且计时停止。插回原 USB 口后，确认监听恢复并开始新的一段计时。
3. 选择轻量、均衡、扩展，核对回读档位、采样覆盖和客户端列表。验证关注规则在短暂断连后保留，在设备整机重启后清空。
4. 在受控测试中用模拟高危告警检查档案、重复投递、确认和过期。以 Android 通知权限开启、锁屏和 Wi-Fi 变化为条件分别确认持续接收。
5. 检查有线 SSH、服务启动及回滚。功耗、掉线恢复、后台运行、SD 写入和 2 GB 设备资源目标以实机记录为准。
