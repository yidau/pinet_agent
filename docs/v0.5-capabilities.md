# PocketNet AI V0.5

## 连接与能力状态

手机建立 MCP 会话后，先请求标准 `tools/list`，再调用 `get_capability_status`。两份结果按工具名对应。状态接口返回 `capabilities` 数组，每项包含 `name`、`status` 和 `domain`。MCP 工具定义继续使用标准字段。

| 状态 | 含义 |
| --- | --- |
| `AVAILABLE` | 实现已经就绪，当前能够查询。 |
| `UNAVAILABLE` | 功能尚未实现。 |
| `DEGRADED` | 已实现的功能缺少数据源或权限等运行条件。 |
| `ERROR` | 已实现的功能在采集时发生错误。 |

设备面板按领域列出所有注册能力。Agent 仅使用当前会话中状态为 `AVAILABLE` 且声明为只读的工具。连到旧服务时，缺失的能力状态显示为「未报告」，升级树莓派服务并重连后即可使用能力状态。

| 领域 | 当前能力 |
| --- | --- |
| 设备 | 系统、CPU、内存、磁盘和能力状态查询 |
| 无线发现 | 5 项规划工具 |
| 无线监测 | 4 项规划工具 |
| 网络发现 | 5 项规划工具 |
| 报文分析 | 5 项规划工具 |
| 安全分析 | 5 项规划工具 |
| 网络诊断 | 4 项规划工具 |

V0.5 共注册 33 项。28 项规划工具显示为「未实现」，调用返回 MCP `isError`、错误码 `CAPABILITY_NOT_IMPLEMENTED` 及 `data: null`。状态接口检查已有四项设备采集能力。设备结果保留原字段、数据来源和 UTC 时间戳。

Overview 展示实际设备信息、网络指标和 AI 调查入口。Wireless 和 Captures 按工具状态呈现空状态或观测结果。信号图只使用采集工具返回的 RSSI 样本。 [Material 3 导航栏](https://m3.material.io/components/navigation-bar/overview) · [Material Symbols](https://developers.google.com/fonts/docs/material_symbols)

## 更新已有树莓派

在树莓派上进入包含 V0.5 的源码仓库。若 MCP 已从该仓库运行，更新代码后重启服务即可。分目录部署时，用下面的命令复制三个模块。原服务的 `--workspace` 仍用于确定磁盘采集位置。

```bash
(
  set -eu
  repo_root="$(git rev-parse --show-toplevel)"
  install_root="$(systemctl show piagent-mcp.service -p WorkingDirectory --value)"
  test -n "$install_root"
  target="$install_root/raspberry/mcp_server"
  test -f "$target/server.py"
  if ! test "$repo_root/raspberry/mcp_server/server.py" -ef "$target/server.py"; then
    owner="$(stat -c '%u' "$target/server.py")"
    group="$(stat -c '%g' "$target/server.py")"
    mode="$(stat -c '%a' "$target/server.py")"
    sudo install -o "$owner" -g "$group" -m "$mode" \
      "$repo_root/raspberry/mcp_server/"{capabilities,device_observations,server}.py "$target/"
  fi
  sudo systemctl restart piagent-mcp.service
  systemctl is-active piagent-mcp.service
)
```

使用同一 Android 签名覆盖安装手机 App，可以继续使用已有的注册信息。连接后打开「设备能力」，核对系统等设备查询可用、规划工具显示「未实现」。接着切换四个页签，查看无线和抓包空状态，并在 AI 中查询系统信息。
