# PocketNet AI V1.0 遥测与消息

V1.0 在 Ubuntu 上增加独立的 C++ 遥测服务。它每秒采样 Linux 指标，定期从 loopback 上的 Kismet 读取指定 USB 监听源的观测元数据。手机通过 gRPC 获得每三秒更新一次的快照，重要变化在事件写入后推送。手机离线时，树莓派继续采样和保存事件。

服务借鉴了采集与上传分离、累计计数差分和连续样本判断，按单设备部署实现。[MonitorSystem 架构与工作流](https://github.com/Chenyu2046/MonitorSystem#架构入口与工作流workflow)

## 架构与数据判读

- **管理热点与监听。** 内置无线电为手机提供管理热点，外接 USB 网卡承担被动观测。配置和热插拔步骤见[外接 USB 无线观测](v1.0-wireless-manager.md)。
- **Linux 指标。** CPU 使用率以两次累计采样的差值计算。磁盘速率由块设备累计计数换算，磁盘忙碌时间单独呈现。温度、频率、PSI 和 Kismet 计数可缺省，手机显示未知。每份 Linux 和 Kismet 指标附采样时间。
- **无线覆盖。** Kismet 统计仅覆盖已经观测并可归因的数据。无线摘要最多读取最近五分钟、最多 128 条来源记录，有界重点 AP 用于展示变化。混合来源无法准确归因的设备或事件会略过。缺少可归因的告警不提供安全结论。现有 Kismet 日志保持关闭，实时接口只导出元数据。
- **资源策略。** CPU、内存或 I/O 的 PSI 连续三个样本达到阈值时产生压力事件；遥测服务降低 Kismet 摘要查询频率，并在压力恢复后产生恢复事件。监听源继续按原设置运行。
- **身份。** 遥测监听管理热点地址上的 TCP 9443，使用注册时已信任的设备证书、手机 ID 和令牌。服务只读查询现有注册数据库，已连接的手机也会定期重新检查资格。旧版 MCP 端口和主动操作路径仍可用。

树莓派的事件队列上限是 128 条，SQLite 保留最多 4096 条。压力下优先保留 P0/P1，合并重复待写事件，并优先淘汰较低优先级的历史。手机最多保存 500 条消息，历史和重连游标按设备区分。快照仅保留当前值。重连先给出完整快照，再从手机已持久化的序号补发剩余事件。已淘汰的序号明确报告为历史缺口。事件序号跨设备重启继续递增，事件 ID 以启动标识和事件库标识为前缀。事件库重建时，手机重新从保留历史的起点同步。

## 在树莓派上构建与安装

先确认目标 Ubuntu 的版本、ARM64 架构和 MCP 配置。现有 PiAgent 注册数据库和管理热点应已配置。优先在 Windows 上通过 WSL 或容器交叉编译，使用与目标 Ubuntu 匹配的 ARM64 工具链和系统库。需要在目标机本地构建时，在仓库根目录执行以下步骤。

```bash
uname -m
cat /etc/os-release
sudo apt-get install cmake make g++ pkg-config protobuf-compiler protobuf-compiler-grpc \
  libprotobuf-dev libgrpc++-dev libssl-dev libsqlite3-dev libcurl4-openssl-dev nlohmann-json3-dev
cmake -S raspberry/telemetry -B /tmp/piagent-telemetry-build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build /tmp/piagent-telemetry-build --parallel 2
sudo cmake --install /tmp/piagent-telemetry-build
sudo install -m 0644 raspberry/telemetry/piagent-telemetry.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now piagent-telemetry.service
```

单元默认复用 `/etc/piagent-https/server.key`、`server.pem` 和 `/var/lib/piagent-devices/devices.sqlite3`。如果现机的服务路径不同，使用 systemd drop-in 调整 `LoadCredential`、`PIAGENT_DEVICE_REGISTRY` 与监听地址。手机从已配对的 MCP 地址获得主机名，固定使用 9443。现有证书的 SAN 必须匹配该主机名或热点 IP；按现有授权方式读取现有注册数据库。

更新现有 MCP 的 CPU 与内存工具，使它们读取同一份 C++ 采样。按实际服务账户和工作目录部署 `device_observations.py`，再应用下列 drop-in。MCP 从 `/run/piagent-telemetry/system.json` 读取最新样本。未升级到 V1.0 的设备仍可以按原方式查询。文件系统空间仍由 MCP 按工作目录查询。

```bash
(
  set -eu
  work=$(systemctl show piagent-mcp.service -p WorkingDirectory --value)
  worker=$(systemctl show piagent-mcp.service -p User --value)
  test -n "$work"
  test -n "$worker"
  test -d "$work/raspberry/mcp_server"
  sudo install -o "$worker" -m 0600 raspberry/mcp_server/device_observations.py "$work/raspberry/mcp_server/"
  sudo install -D -m 0644 raspberry/telemetry/mcp-telemetry.conf \
    /etc/systemd/system/piagent-mcp.service.d/50-telemetry.conf
  sudo systemctl daemon-reload
  sudo systemctl restart piagent-mcp.service
)
```

## 本地与实机验收

电脑或 WSL 可运行：

```bash
cmake -S raspberry/telemetry -B /tmp/piagent-telemetry-check -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/piagent-telemetry-check --parallel 2
(cd /tmp/piagent-telemetry-check && ctest --output-on-failure)
python -m unittest tests.test_wireless_manager tests.test_telemetry_cache
```

WSL x86_64 已通过 C++ 编译和三项本地测试，覆盖 Linux 与模拟 Kismet 数据、SQLite 优先级保留、TLS 授权、重放和撤销断流。Windows 上 Python 回归 25 项、Flutter 测试 20 项及 Flutter 静态分析通过。在 ARM64 树莓派上已完成原生构建、systemd 安装，并确认遥测监听和系统快照。USB 网卡驱动、热点共存、手机 TLS 和系统休眠后的重连由设备所有者实机验收。

1. 用现有注册手机连接管理热点并打开 V1.0。仪表盘应显示持续更新的 CPU、可用内存及采集状态。设备未提供温度或 PSI 时应显示未知。设置菜单保留无线详情与采集文件入口。
2. 保持手机在线，拔下外接网卡。热点仍应可用，仪表盘显示采集受限，消息中心收到变化。重新插入已配置的 USB 端口后核对恢复通知。
3. 先断开手机，再重复一次拔插。重新连接后确认收到最新快照与仍保留的事件。重新打开消息中心核对历史与未读状态。
4. 用树莓派端下列只读命令核对服务和监听。未注册的手机没有遥测订阅权限。

```bash
systemctl status --no-pager piagent-telemetry.service piagent-kismet.service
journalctl -u piagent-telemetry.service -b -n 30 --no-pager
ss -ltn | grep ':9443'
```

指标依据见 [Linux 磁盘统计](https://docs.kernel.org/admin-guide/iostats.html)、[Linux PSI](https://docs.kernel.org/accounting/psi.html) 和 [Kismet 数据源 API](https://www.kismetwireless.net/docs/api/datasources/)。
