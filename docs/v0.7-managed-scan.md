# V0.7 · 普通 Wi-Fi 扫描与 H1–H4 实机验收

本页操作由设备所有者在自己的树莓派上执行。当前硬件验收状态为**待用户验证**。在树莓派安装 V0.7 模块并运行 `sudo python3 raspberry/config/kismet/configure.py` 后，管理员可以手动发起一次扫描。命令从有线 SSH 执行，手机可继续通过热点检查 MCP。先给系统 Python 安装对应组件。

```bash
sudo apt-get install --no-install-recommends iw python3-pyroute2
```

配置脚本默认选择 `wlan0`，可通过 `--scan-interface 接口名` 选择另一块无线网卡。systemd 单次服务以独立账户和 `CAP_NET_ADMIN` 使用 nl80211，只向本机 Kismet 的扫描报告接口提交结果。Kismet 的 `scanreport` 角色密钥、稳定 UUID 由配置脚本保存在树莓派的 `/etc/piagent-kismet/managed-scan.env`。MCP 使用原来的只读角色。安装完成后等待管理员发起扫描。软件适配核对了 Ubuntu 26.04 发行包 `python3-pyroute2 0.8.1-4` 中的 `IW.scan`、接口枚举和 BSS 解码定义。[Ubuntu 包记录](https://api.launchpad.net/1.0/ubuntu/+archive/primary/+binarypub/240741314)

## H1 · 检查接口

```bash
iw dev
iw list
iw dev wlan0 info
```

记录接口名、phy、`type`、支持的接口模式和组合。`type AP` 表示此接口正在提供热点。其他接口如果位于同一 phy，也在共用这块无线电。支持某个接口模式无法单独证明扫描期间热点稳定。

## H2 · 一次普通扫描

先确认现场可以尝试一次普通 Wi-Fi 扫描，且手机有正在使用的管理连接时可以同时观察连接。若无法确认可安全尝试，可记录「待验证」并保留热点。条件具备时，用实际接口名执行以下命令。

```bash
sudo iw dev wlan0 scan
```

记录 BSS、频率、信号、SSID，以及驱动返回的完整错误。隐藏网络可能没有可显示的 SSID。未发现记录可以是一次成功但为空的扫描。若返回 `Operation not supported` 或 `Device or resource busy`，保留原配置并记录当前并发条件受限。

## H3 · 和热点并发

让另一台手机保持连接 `PiAgent` 热点。在下列两条启动命令中，按 H1 的结果选一条。独立 managed 接口使用第一条。普通模式检测到选中的 phy 同时承担热点时会返回 `DEGRADED`。仅在操作者明确同意本次共存试验并可以观察连接时，使用第二条。

```bash
sudo systemctl start piagent-managed-scan@normal.service
# 共用热点无线电，明确同意本次尝试后使用
sudo systemctl start piagent-managed-scan@shared-ap.service
```

在该手机上刷新 MCP 能力并完成一次 BLE 校时，记录热点连续性、校时结果和扫描是否成功。服务只扫描一次，最多等待约 22 秒，不切换网卡工作模式。正在运行的试验可在另一个有线终端中停止。如果发现共存冲突，执行以下命令结束试验、撤回本次缓存，并将 Wi-Fi Scanning 标记为条件不足。

```bash
sudo systemctl stop piagent-managed-scan@shared-ap.service piagent-managed-scan@normal.service
sudo systemctl start piagent-managed-scan@hold.service
```

## H4 · 比对 Kismet 与手机

```bash
sudo journalctl -b -u 'piagent-managed-scan@*.service' -n 20 --no-pager
sudo python3 -m json.tool /run/piagent-managed-scan/status.json
```

成功时日志显示 `AVAILABLE submitted=N`。在手机 Wireless 页刷新 Wi-Fi Networks，核对一行已知 AP 的 BSSID、SSID、信道、RSSI 和 Managed Scan 来源。查看对应的 Kismet 数据源 UUID，重复一次授权扫描应得到相同 UUID。如果实际结果为空，记录数量为零，再在有已知 AP 的条件下完成字段比对。

下面的只读命令从该 UUID 对应的 Kismet 设备视图中取最多五行，对照本次报告的 BSSID。这里读取当前 Kismet 内存中的设备记录。设备视图可能保留该数据源先前发现的 AP。

```bash
sudo python3 - <<'PY'
import json
from pathlib import Path
from urllib.parse import urlencode
from urllib.request import ProxyHandler, Request, build_opener
env = dict(line.split("=", 1) for line in Path("/etc/piagent-kismet/client.env").read_text().splitlines() if line)
scan = json.loads(Path("/run/piagent-managed-scan/status.json").read_text())
if scan["status"] != "AVAILABLE":
    raise SystemExit(scan["reason"])
base = env["PIAGENT_KISMET_URL"]
headers = {"Cookie": "KISMET=" + env["PIAGENT_KISMET_API_KEY"]}
http = build_opener(ProxyHandler({}))
with http.open(Request(base + "/datasource/all_sources.json", headers=headers), timeout=3) as response:
    uuids = [row["kismet.datasource.uuid"] for row in json.load(response)]
source_uuid = next((u for u in uuids if u.lower() == scan["source_uuid"].lower()), None)
if source_uuid is None:
    raise SystemExit("Kismet 没有当前报告的数据源，请重新执行一次授权扫描。")
url = base + "/devices/views/seenby-" + source_uuid + "/devices.json"
fields = ["kismet.device.base.macaddr", "kismet.device.base.name", "kismet.device.base.channel"]
form = urlencode({"json": json.dumps({"fields": fields, "datatable": True}), "start": 0, "length": 5, "draw": 1})
request = Request(url, data=form.encode(), headers=headers)
with http.open(request, timeout=3) as response:
    print(json.load(response)["data"])
PY
```

每次最多保留 128 个 AP，截断时返回 `truncated=true`。新观测可查询 5 分钟。缺少无线信息的字段为 `null`。Kismet 会把缺少加密信息的报告理解为开放网络，所以无法确定安全配置的记录只出现在实际扫描快照，标记 `kismet_reported=false`。扫码注册使用的二维码和两种 Kismet 密钥均无需发给手机或附在验收记录中。[Kismet 扫描报告接口](https://www.kismetwireless.net/docs/api/wifi_scanningmode/) · [Kismet 设备视图](https://www.kismetwireless.net/docs/api/device_views/) · [pyroute2 IW](https://github.com/svinota/pyroute2/blob/master/pyroute2/iwutil.py)
