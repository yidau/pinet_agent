# V1.0 外接 USB 无线观测

内置无线电继续提供 PiAgent 管理热点。一个配置明确的 USB 无线电用于 Kismet 被动观测。现有 `piagent-kismet.service` 仍是唯一的 Kismet 实例，用户拔插外接网卡时无需重启热点或 Kismet。

## 设备所有者配置

在树莓派上核对实际系统、接口和设备信息。选择兼容当前系统和 CPU 架构的 `iw`、Kismet 核心及同版本的 `kismet-capture-linux-wifi`，以安装包提供的受限权限运行采集助手。Ubuntu 版本、CPU 架构、外接芯片和驱动以现场输出为准。

```bash
uname -m
cat /etc/os-release
lsusb
iw dev
iw phy
```

把 `MON_IF` 设置为 `iw dev` 中明确属于外接网卡的接口。通过 udev 查 VID、PID 与驱动。PHY 设备的路径中形如 `1-1.2` 的最后一级 USB 设备结点是 `--port` 参数。对于以 `1-1.2:1.0` 结尾的 USB 接口路径，设备结点为 `1-1.2`。以上数字只是格式示例。

```bash
udevadm info --query=property --path="/sys/class/net/$MON_IF" | \
  grep -E '^(ID_BUS|ID_PATH|ID_VENDOR_ID|ID_MODEL_ID|ID_NET_DRIVER)='
readlink -f "/sys/class/net/$MON_IF/phy80211/device"
```

从仓库根目录执行，使用刚核对的 `MON_VID`、`MON_PID`、`MON_PORT` 和 `MON_DRIVER`。等待正在运行的单次扫描结束后安装。安装脚本准备配置和单元，为指定设备生成 `pn-wifi0` 专用接口名，依据 USB 路径、VID/PID 和驱动匹配。若已安装旧版普通扫描助手，脚本会更新它以识别专用监听端口。对管理热点的单次扫描仍受原来的操作确认和 PHY 规则约束。

```bash
sudo python3 raspberry/config/kismet/configure_monitor.py \
  --interface "$MON_IF" --vendor "$MON_VID" --product "$MON_PID" \
  --port "$MON_PORT" --driver "$MON_DRIVER"
sudo udevadm control --reload
```

仅重新插拔已选定的 USB 网卡，使 udev 命名生效。然后应用 Kismet 助手权限并启动管理器。Kismet 主进程仍使用 `piagent-kismet` 用户。单独的 systemd 覆盖允许受限安装的助手获得所需权限。

```bash
sudo systemctl restart piagent-kismet.service
sudo systemctl enable --now piagent-wireless-manager.service
```

## 实机验收

```bash
iw dev
systemctl is-active piagent-hotspot.service piagent-kismet.service piagent-wireless-manager.service
cat /run/piagent-wireless/monitor.json
journalctl -u piagent-wireless-manager.service -u piagent-kismet.service -b -n 50 --no-pager
```

1. 手机连接管理热点。确认热点接口与 `pn-wifi0` 位于不同的 PHY。
2. 正常启动后，管理器报告 `ready` 和 Kismet 数据源 UUID。`starting` 表示已请求启动，`degraded` 的 `reason` 说明设备、驱动、数据源或 Kismet 的当前限制。轮询间隔约 5 秒，错误后的重试会退避。
3. 保持手机在管理热点内，拔掉 USB 网卡。管理器应报告 `degraded`，Kismet 和热点继续运行。插回同一物理端口后，确认恢复到 `ready`，使用同一数据源 UUID。插到其他端口时，当前身份配置应保持降级。
4. 对照 Dashboard 检查数据源和无线摘要。API 未提供或数据源暂不可用的指标显示为未知。现场观察只能说明该设备和当时环境下的观测覆盖范围。

## 观测数据范围

实时链路提供设备、无线环境和告警的元数据。Kismet 继续使用 loopback API 和关闭日志的启动选项，并关闭握手缓存。管理器只负责已分配的数据源。`filter_mgmt` 会同时放行认证管理数据，本实现保留元数据观测，并将帧级过滤兼容性留给用户基于实际安装版本确认。[Kismet Linux Wi-Fi 数据源文档](https://www.kismetwireless.net/docs/readme/datasources/wifi-linux/) · [Kismet 性能调优文档](https://www.kismetwireless.net/docs/readme/performance_and_memory/)

Windows 或 WSL 上可以运行 `python -m unittest tests.test_wireless_manager`，验证身份拒绝、USB 拔插状态迁移和固定数据源操作。实际网卡驱动、服务隔离和热点共存需要在 ARM 设备上验收。
