# V0.7 · 无线观测数据源与验收

本版从 `v0.6.0`（`51bfcaf`）扩展到 51 项 MCP 工具。手机可以查询普通 Wi-Fi 扫描结果、蓝牙观测和离线实验文件。无线操作默认由树莓派管理员手动启动。手机刷新能力、打开 Wireless 页或向 AI 提问，只会读取状态和已有观测。

## 从 V0.6 更新

以下是供设备所有者执行的树莓派命令。先把本版源码放到树莓派上，从源码根目录执行。新设备先按 [README](../README.md) 安装注册、热点、蓝牙和 MCP，再按 [Kismet 软件包安装说明](v0.6-kismet.md#在-ubuntu-arm64-设备安装) 安装与系统发行版匹配的 Kismet 核心包。已有 V0.6 设备可以沿用 Kismet 和手机注册信息。

```bash
# 系统 Python 运行单次普通扫描。Kismet 核心包提供文件重放组件。
sudo apt-get install --no-install-recommends iw python3-pyroute2

(
  set -eu
  mcp_root=$(systemctl show -p WorkingDirectory --value piagent-mcp.service)
  test -n "$mcp_root"
  test -d "$mcp_root/raspberry/mcp_server"
  if [ "$(realpath raspberry/mcp_server)" != "$(realpath "$mcp_root/raspberry/mcp_server")" ]; then
    sudo install -m 0644 raspberry/mcp_server/*.py "$mcp_root/raspberry/mcp_server/"
  fi
  sudo python3 raspberry/config/kismet/configure.py --scan-interface wlan0
  sudo python3 raspberry/config/kismet/configure_sources.py
  sudo systemctl restart piagent-kismet.service piagent-mcp.service
)
```

接口名根据 H1 的实际结果填写。已有自定义 Kismet 管理端口的设备，给 `configure.py` 传入原来的 `--port`。Kismet、报告程序和本机重放控制分别持有所需凭据；手机使用原 MCP 设备令牌。需要 H5 时再安装与发行版匹配的 Linux Bluetooth helper，见下表。

| 手机上显示的来源 | 数据如何产生 | 可用条件 |
| --- | --- | --- |
| Wi-Fi Managed Scan | 管理员触发单次 nl80211 扫描，报告程序向本机 Kismet 提交 AP 记录 | 有本次启动后 5 分钟内获 Kismet 确认的快照，且能在 Kismet 找到同一虚拟源 UUID。即使本次真实扫描发现 0 个 AP，也可报告成功 |
| Wi-Fi Monitor Mode | 来自运行中的 Linux Wi-Fi 监听源的既有观测 | Kismet 报告该源正在运行，并可读取其专属设备视图。只有普通扫描时，客户端发现和信号历史仍受限 |
| Bluetooth Active Scan | 管理员手动启动限时 Linux HCI 发现 | Kismet 报告指定蓝牙源正在运行，并能读取该源的蓝牙设备。独立于 Wi-Fi AP 列表 |
| PCAP Replay | 从专用目录读取 PCAP、PCAPNG 或 KismetDB，交给 Kismet 文件源离线重放 | 文件校验、对应 helper、控制服务和管理员授权就绪。Captures 页可查看文件、元信息和重放状态 |

`scan_wireless_environment` 延续 V0.6 的只读语义，只汇总已有观测。`get_kismet_datasource_status` 分别返回四类来源的状态及原因。`replay_capture(capture_id, confirm)` 与 `stop_capture_replay(confirm)` 属于写操作，服务端执行授权及参数检查，Flutter 的只读 Agent 工具列表会滤除它们。Kismet 自身的全局设备清单保留各来源的历史记录；查找当前 AP 或蓝牙设备请使用 Wireless 页的对应区域。

## 手机使用

覆盖安装 V0.7 ARM64 APK 后，连回原 PiAgent 热点，打开「连接设备」及「设备能力」。点刷新查看四类来源的状态和原因。Wireless 页分别显示 Wi-Fi Networks 和 Bluetooth Devices；Captures 页点文件可读取元信息。保持手机可访问云端后，可在 AI 页问「哪些来源当前可用？最近一次普通 Wi-Fi 扫描观测到了什么？」。没有观测时，回答应说明原因。
