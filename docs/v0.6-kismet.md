# PocketNet V1 Kismet 无线采集

Kismet 是 PocketNet 唯一的原始无线采集引擎，由 systemd 常驻运行。C++ Telemetry 服务通过本机 loopback REST API 读取 Kismet 状态、设备摘要和统计；重要告警通过独立的 Kismet Eventbus 接入。手机业务通信只使用 TLS gRPC/Protobuf。

## 采集架构

- 内置 Wi-Fi：只提供 PocketNet 管理热点。
- 外接 USB Wi-Fi：按 VID/PID、USB 端口、驱动和 PHY 绑定到固定 Monitor 接口。
- Kismet：持续运行，不由手机查询或 MCP 请求按需启动。
- 受管 Linux Wi-Fi datasource：definition 包含 `filter_mgmt=true`，保留 802.11 管理帧和 EAPOL。
- C++ Telemetry：读取 Kismet loopback API 和告警事件，不建立第二个抓包 socket。

## 数据边界

在 `filter_mgmt=true` 下，可用于 AP 发现、Beacon/Probe/Authentication/Association/Deauthentication 等管理活动观察，以及 EAPOL 认证帧活动统计。普通 Data Frame 被过滤，因此不能据此提供完整 ARP、DNS、TCP 或 WLAN 带宽分析。Kismet 的收包/处理计数必须按其统计口径展示，不能等同于空口总丢包。

## 配置与诊断

安装 Kismet 核心及匹配版本的 Linux Wi-Fi capture helper 后，先配置 loopback-only API 和关闭抓包日志：

```bash
sudo python3 raspberry/config/kismet/configure.py --port 2501
```

然后由设备所有者检查 USB 网卡，并执行 [V1 无线管理器配置](v1.0-wireless-manager.md)。

```bash
systemctl is-active piagent-kismet piagent-wireless-manager piagent-telemetry
journalctl -u piagent-kismet -u piagent-wireless-manager -u piagent-telemetry -b -n 80 --no-pager
```

不要将无法证明来源的 Kismet 实例级告警标记为来自当前实时 Monitor 网卡。多数据源存在时，来源不确定必须明确展示。
