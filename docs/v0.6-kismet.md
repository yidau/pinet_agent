# V0.6 · Kismet 本机无线观测

手机沿用已注册的热点、设备身份和 HTTPS MCP 入口。MCP 经 Wireless Service 和只读 REST Adapter 查询本机 Kismet。当前树莓派使用内置 Wi-Fi 提供热点，外置采集网卡尚未接入。

## 在 Ubuntu ARM64 设备安装

先完成 [基础服务安装](../README.md)，或在已有 V0.5 设备上准备好 V0.6 源码。以下命令适用于已确认发行版代号的 Ubuntu ARM64 树莓派。官方仓库按发行版和架构提供软件包，本次使用 Ubuntu 26.04 `resolute` 对应的 release 仓库。[Kismet 软件包与支持列表](https://www.kismetwireless.net/packages/)

```bash
. /etc/os-release
printf '%s %s\n' "$PRETTY_NAME" "$(dpkg --print-architecture)"
# 确认上述系统与官方仓库的发行版和架构匹配后，在可联网的树莓派上执行
curl -fsSLo /tmp/piagent-kismet-signing-key.asc https://www.kismetwireless.net/repos/kismet-release.gpg.key &&
  sudo gpg --batch --yes --dearmor -o /usr/share/keyrings/kismet-archive-keyring.gpg /tmp/piagent-kismet-signing-key.asc
printf 'deb [arch=arm64 signed-by=/usr/share/keyrings/kismet-archive-keyring.gpg] https://www.kismetwireless.net/repos/apt/release/%s %s main\n' \
  "$VERSION_CODENAME" "$VERSION_CODENAME" | sudo tee /etc/apt/sources.list.d/kismet.list >/dev/null
sudo apt-get update
apt-cache policy kismet-core
sudo apt-get --simulate --no-install-recommends install kismet-core
sudo apt-get --no-install-recommends install kismet-core
```

本次现场使用没有默认网关的有线连接。电脑下载官方 Kismet 公钥、签名的 `InRelease`、ARM64 `Packages.gz` 和核心包，并按目标机 APT 给出的具体版本下载缺少的 Ubuntu 依赖。传入树莓派后使用 `gpgv` 验证签名，逐级校验索引、核心包和 Ubuntu 依赖的 SHA-256，随后安装。安装的核心包版本为 `2026-10-R1`。

从 **V0.6 源码根目录**执行以下命令。脚本读取已安装 Kismet 配置中的 HTTP 端口，并把同一端口写入服务与客户端配置。有端口冲突时，可传入 `--port 另一个空闲端口`。

```bash
mcp_root=$(systemctl show -p WorkingDirectory --value piagent-mcp.service)
test -n "$mcp_root" && test -d "$mcp_root/raspberry/mcp_server" &&
  sudo install -m 0644 raspberry/mcp_server/{capabilities,server,kismet_adapter,wireless_service}.py \
    "$mcp_root/raspberry/mcp_server/" &&
  sudo python3 raspberry/config/kismet/configure.py &&
  sudo systemctl restart piagent-mcp.service
systemctl is-enabled piagent-kismet.service
systemctl is-active piagent-kismet.service piagent-mcp.service
```

Kismet 以专用用户运行，在异常退出后由 systemd 重启。Kismet 只绑定回环地址。安装脚本在树莓派上生成管理凭据，并给 MCP 单独签发 `readonly` 密钥。MCP 通过 systemd 环境文件读取密钥。无源配置关闭远程采集入口和抓包日志，设备内存记录上限为 512，告警历史上限为 50。服务启动时的诊断可通过 `journalctl -u piagent-kismet -b` 查看。[Kismet 登录角色](https://www.kismetwireless.net/docs/api/login/) · [Kismet 配置](https://www.kismetwireless.net/docs/readme/configuring/configfiles/)

## 手机能看到什么

| 能力 | 当前无采集源、API 正常时 | 可查询的内容 |
| --- | --- | --- |
| 系统与能力目录（5 项） | `AVAILABLE` | 系统、CPU、内存、磁盘、能力清单 |
| Kismet（6 项） | `AVAILABLE` | 运行状态、版本、数据源、已记录设备、告警、采集状态 |
| 依赖采集源的无线查询（7 项） | `DEGRADED` | 环境摘要、AP 列表与详情、已观测客户端、信道、信号历史、无线事件 |
| 规划中的功能（27 项） | `UNAVAILABLE` | 包括启动或停止监听、PCAP 分析与安全检测 |

状态由 `get_capability_status` 按 `tools/list` 的名字返回。设备能力面板可手动刷新，打开 Wireless 页和发起 AI 查询也会刷新。API、认证或响应格式出错时，受影响的能力显示 `ERROR`。运行中失去采集源时，AP 查询会返回 `isError=true`、`status=degraded`、`error_code=CAPABILITY_UNAVAILABLE`、`data=null`。

后续接入已由 Kismet 配置并成功运行的 Linux Wi-Fi 采集源，手机可查询已有观测。每次设备视图最多读取 32 条，结果包含总量和截断标志。信号历史需要真实的 dBm 样本。Kismet 自身的运维告警和从无线环境观测到的事件在界面上分开展示。[设备视图 API](https://www.kismetwireless.net/docs/api/device_views/) · [告警 API](https://www.kismetwireless.net/docs/api/alerts/)

### 手机复验步骤

使用已注册的手机连接原来的 PiAgent 热点，点击「连接设备」，打开「设备能力」。在当前硬件条件下应看到 Kismet 运行、数据源为 0，Wireless 页显示缺少可用采集源。保持手机可以访问云端，在 AI 页询问「Kismet 版本是多少？现在能看到哪些 AP？」。回答应引用设备版本并说明缺少采集源。最后打开「蓝牙校时」，选择树莓派并点「开始校时」，确认手机收到「校时成功」。
